# Alpaca Adapter Capture Contract

This contract describes what an Alpaca adapter must capture before an InnerOS
Alpha recommendation is normalized, scored, or acted on.

## Boundary

The forensic replay core does not talk to Alpaca, import Alpaca clients, store
credentials, place orders, or fetch live market data during replay.

The adapter is responsible for authenticated reads only. It must pass raw
payloads into `EvidenceBundleWriter` immediately after the API response is
received.

## Required Artifacts

- `alpaca.latest_trade.raw`: raw latest trade payload for every symbol used by
  the decision.
- `alpaca.bars.raw`: raw bars payload, including timeframe, limit, adjustment
  mode and the exact symbols requested.
- `alpaca.option_chain.raw`: raw option-chain payload and request filters used
  by the decision.
- `alpaca.portfolio.raw`: raw account, cash, buying-power, position and order
  state used by the decision.

## Required Metadata

Each artifact should include:

- `observed_at`: source timestamp or response timestamp when the market state
  was observed.
- `captured_at`: generated by the bundle writer when bytes are persisted.
- `source`: Alpaca endpoint or adapter method name.
- `metadata`: request parameters, environment label (`paper` or `live`) and
  adapter version.

## Replay Rules

- Missing artifacts fail closed.
- Hash mismatches fail closed.
- Audit Replay can inspect preserved payloads only.
- Deterministic Replay can run local policy/normalization code only.
- Live refresh, order placement and account mutation are forbidden during replay.

## Minimal Adapter Flow

```python
writer = EvidenceBundleWriter(bundle_dir, correlation_id=correlation_id)
capture_alpaca_snapshot(writer, snapshot)
manifest = writer.write_manifest(
    policy={"risk_policy_version": "inneros-alpha-risk-v1"},
    trace={"source": "inneros-alpha"},
)
```
